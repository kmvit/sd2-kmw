# Сайт завода на Django

Django 5.1, SQLite, без внешних зависимостей кроме Pillow. Набор страниц задан
кодом, а тексты, прайсы и справочники правятся в админке.

## Запуск

```bash
python3 -m venv .venv && .venv/bin/pip install -r requirements.txt
.venv/bin/python manage.py migrate
.venv/bin/python manage.py seed_content      # контент из вёрстки в базу
.venv/bin/python manage.py seed_redirects    # карта 301 со старых адресов
.venv/bin/python manage.py createsuperuser
.venv/bin/python manage.py runserver 8899
```

Сайт — http://localhost:8899, админка — http://localhost:8899/admin/

## Структура

```
sd2_site/        настройки и корневые маршруты
core/            настройки сайта, страницы, блоки страниц, плитки, документы
catalog/         прайсы: бетон, растворы, инертные, асфальт, блоки, плитка,
                 группы и позиции ЖБИ, направления доставки, бетононасосы
content/         команда, сертификаты, партнёры, объекты, вопросы, история
leads/           заявки и письма директору, формы, отправка уведомлений
pages/           маршруты, представления, наполнение базы (pages/seed/)
templates/       базовый шаблон, общие блоки (partials/), страницы (pages/)
static/          дизайн-система, фотографии, иконки
media/           файлы, загруженные через админку (в репозиторий не идут)
docs/            заметки по проекту
```

## Как устроены страницы

Набор страниц и их вёрстка заданы кодом: список маршрутов — в `pages/views.py`,
шаблон каждой страницы — в `templates/pages/`. Из базы приходят:

- `Page` — заголовок, подзаголовок, фото шапки и SEO-поля;
- `Section` — штамп, заголовок, вводный текст, примечание и фото каждого блока.
  Блок можно скрыть или переставить, не трогая шаблон;
- `Card` — плитки внутри блока: шаги, преимущества, цифры, пункты списков;
- справочники — прайсы, команда, сертификаты, объекты, вопросы.

Страницы товаров ЖБИ (19 штук) собираются из `ZhbiGroup` и её позиций.
У плитки и стеновых блоков своя вёрстка — она подключается полем «Свой шаблон».

## Команды

```bash
python manage.py seed_content            дополнить контент
python manage.py seed_content --reset    залить заново (заявки не трогает)
python manage.py seed_redirects          редиректы со старых адресов
```

## Тестовая площадка

Сайт развёрнут на техническом домене сервера: https://77dbc7754866.vps.myjino.ru

Обновление после правок кода:

```bash
./deploy.sh              # код, зависимости, миграции, статика, перезапуск
./deploy.sh --seed       # плюс залить контент (нужно только на пустой базе)
```

На сервере: код в `/opt/sd2`, база и медиафайлы там же и при выкладке
не перезаписываются, служба `sd2` (gunicorn на 127.0.0.1:8002), nginx
проксирует и сам отдаёт `/static/` и `/media/`. Переменные окружения —
в `/opt/sd2/.env`, логи: `journalctl -u sd2 -n 100`.

## Перед переездом на рабочий домен

1. Снять галочку «Закрыть сайт от индексации» в общих данных сайта.
2. Заполнить адреса для заявок и личную почту директора — иначе письма никуда
   не уйдут, заявки останутся только в админке.
3. Указать номер счётчика Метрики.
4. Проверить карту редиректов и отправить новую `sitemap.xml` в вебмастер.
5. Заменить просроченные сертификаты и временные фотографии — см.
   [docs/notes.md](docs/notes.md).

## Вёрстка

Исходная статическая вёрстка осталась в `src/` и собирается `build.py` —
она больше не используется сайтом, но пригодится как эталон при сверке.
Снимки страниц для заказчика делает `shots.py`.
